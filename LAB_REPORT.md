# Лабораторная работа 3

Выбор средств обработки информации и распределение ролей. Вариант 1. Работа выполнена индивидуально.

## Задание 1 Выбор средств обработки информации

**1. Система и назначение.** Вариант 1 — интернет-магазин товаров для хобби и творчества. Начальный ассортимент — около 500 позиций с дальнейшим ростом. Система объединяет каталог, корзину, онлайн-оплату, личный кабинет, скидки, управление заказами и складом, интеграцию с доставкой.

**2. Основные процессы.** Оформление заказа: покупатель выбирает товары, применяет скидку и оплачивает; магазин получает заказ и уведомляет клиента. Учёт склада: система резервирует остатки, списывает отгруженные товары и возвращает резерв при отмене. Доставка: менеджер передаёт заказ службе доставки, отслеживает статус и отправляет уведомления.

**3. Цели.** Запустить онлайн-продажи, сократить ручную обработку заказов, исключить продажу отсутствующих товаров и дать покупателю возможность отслеживать заказ. Целевые показатели: актуальные остатки, корректная сумма и скидки, подтверждение заказа после успешной оплаты.

**4. Программные средства.** Выбрано готовое решение WordPress + WooCommerce. Backend — PHP 8.3 и выше, платформа WordPress и плагины WooCommerce; frontend — HTML, CSS и JavaScript в адаптивной теме. MySQL 8 хранит связанные данные товаров, клиентов, заказов и остатков; транзакции помогают согласованно обновлять данные. Сервер — Linux, Nginx и HTTPS.

**5. Обоснование решения.** Типовые функции магазина уже есть в WooCommerce, оплату и доставку можно подключить модулями, скидки и заказы настраиваются через панель администратора. Для небольшого бизнеса это быстрее и дешевле разработки с нуля. Кастомная разработка потребуется при сложных правилах продаж или нестандартных интеграциях.

**6. Технические средства.** Начальная оценка для умеренной нагрузки: 2 vCPU, 4 ГБ RAM, 60 ГБ SSD и канал 100 Мбит/с. CPU обслуживает PHP и базу, RAM — процессы и кеш, SSD — систему, базу и фотографии. При 500 товарах и пяти оптимизированных фото по 200 КБ изображения займут около 0,5 ГБ; остальной объём нужен для данных, журналов и роста. Резервные копии хранятся отдельно. Это проектная оценка, а не результат нагрузочного теста; при росте нагрузки ресурсы увеличиваются по мониторингу.

**7. Соответствие целям, плюсы и риски.** Готовая платформа покрывает необходимые функции, MySQL обеспечивает хранение связанных данных, сервер оставляет запас для роста. Плюсы: быстрый запуск, доступная поддержка и расширение модулями. Риски: несовместимость и стоимость плагинов, зависимость от обновлений, замедление при росте нагрузки. Меры: проверка обновлений на копии, резервирование, кеширование и контроль состояния сервера.

## Задание 2 Организация работы с Git и GitHub

**1. Участник и роли.** Работа выполнена индивидуально, аккаунт dima3246. Совмещены роли тимлида (планирование, ревью и слияние), разработчика 1 (каталог), разработчика 2 (корзина и заказ), тестировщика и технического писателя (проверки, CHANGELOG и отчёт). Взаимодействие нескольких людей и независимое ревью не заявляются.

**2. Учебный проект и требования.** Создан небольшой прототип магазина: 1) каталог с ценами и остатками; 2) поиск и фильтр категории; 3) добавление и удаление товаров; 4) изменение целого количества в пределах остатка и расчёт суммы; 5) учебный заказ с проверкой имени и email. В прототипе шесть товаров, HTML/CSS/JavaScript и локальное сохранение корзины. Полный магазин из задания 1 является проектным предложением; реальная оплата, доставка и личный кабинет в прототип не входят.

**3. Workflow и регламент.** main содержит итог, develop — проверенную сборку, feature/* — отдельные задачи. Готовые изменения проходят Pull Request, самостоятельное ревью, исправления и тесты, затем включаются в develop. Регламент сохранён в docs/WORKFLOW.md; требования к коммитам, ревью, конфликтам и выпуску указаны там.

**4. Репозиторий и окружение.** Создан публичный репозиторий https://github.com/dima3246/lab3-hobby-shop. Добавлены README.md и .gitignore. Ветка develop создана от main и отправлена на GitHub. Имя и email Git заданы локально для учебного репозитория. Выполнено отдельное git clone, переключение на develop и git pull origin develop; в полученной копии прошли восемь тестов.

**5. Реализация и коммиты.** В feature/catalog реализован каталог, в feature/cart-checkout — корзина, форма заказа и проверки. Логически завершённые изменения зафиксированы отдельными коммитами с понятными сообщениями и отправлены на GitHub. Каталог и корзина включены в develop через PR № 1 и № 2.

**6. Ревью и исправление.** В PR № 2 записано замечание: корзина принимала дробное количество 1,5. Добавлен регрессионный тест, который сначала выявил ошибку. Проверка изменена на целое число, исправление отправлено отдельным коммитом; все восемь тестов прошли. Ревью выполнено автором; одобрение другим участником не имитировалось.

**7. Проверки и история изменений.** После слияний выполнен pull develop. Восемь автоматических тестов проверяют поиск, фильтрацию, расчёт суммы, удаление, ограничения количества и данные покупателя. В браузере проверены поиск «кист», сочетание фильтров, корзина и оформление заказа: две упаковки красок и набор кистей дают 1570 рублей, после заказа корзина очищается. Результаты — docs/TEST_CASES.md, изменения — CHANGELOG.md; тесты также запускаются через GitHub Actions.

**8. Реальный конфликт.** Две ветки feature/readme-catalog и feature/readme-cart изменили одну строку README от общего коммита. Первая включена в develop через PR № 3. Во второй выполнен git merge origin/develop: Git сообщил CONFLICT. Вручную сохранены оба дополнения — «с каталогом и корзиной», маркеры удалены. Создан merge-коммит ff0afb1, затем PR № 4 включён в develop. Исходный конфликт и решение сохранены в docs/CONFLICT_EVIDENCE.md.

**9. Отчёт и выпуск.** В репозитории сохранены LAB_REPORT.md, регламент, тест-кейсы, CHANGELOG и доказательства ревью и конфликта. Документация включается через PR feature/report → develop; итоговый выпуск — через PR develop → main. Все операции доступны в истории GitHub.

**10. Итог.** Обоснован выбор средств для полноценного магазина и выполнен отдельный учебный проект. Отработаны клонирование, ветки, коммиты, push/pull, Pull Request, самостоятельное ревью с исправлением, тестирование и ручное разрешение конфликта. Командные роли совмещены одним участником.

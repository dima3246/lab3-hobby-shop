# Регламент работы

1. Все роли выполняет один участник dima3246: тимлид принимает решения, роль разработчика 1 отвечает за каталог, разработчика 2 — за корзину, тестировщика и писателя — за проверки и документы.
2. main содержит итоговый выпуск, develop — сборку для проверки. Для задачи создаётся feature/* от актуального develop.
3. Перед работой выполняются fetch и pull. Коммиты небольшие, логически завершённые; сообщение описывает действие. Ветки регулярно отправляются через push.
4. Готовая feature-ветка направляется в develop через Pull Request с описанием результата и проверок.
5. Ревью проверяет требования, корректность расчётов, обработку ошибок и читаемость кода. Замечания записываются в PR, исправления — отдельными коммитами. При индивидуальной работе это самостоятельная проверка; независимое одобрение не заявляется.
6. До слияния должны пройти автоматические проверки и основной пользовательский сценарий. Решение о слиянии принимает участник в роли тимлида.
7. После слияния тестировщик обновляет develop через pull, проверяет сборку, обновляет тест-кейсы и CHANGELOG.
8. При конфликте develop сливается в feature-ветку. Конфликтующие изменения сравниваются и объединяются вручную, маркеры удаляются, результат проверяется и фиксируется коммитом. Force push без необходимости не применяется.
9. Итоговый develop включается в main через PR после проверки исходников, отчёта и документов. Секреты, личные данные и временные файлы в репозиторий не добавляются.
